0. Abstract

This work identifies web pages most likely to be declining in performance and in need of editorial refresh review. Using the anonymized FlyRank starter dataset, we compared a simple logistic regression model against a transparent baseline rule on a client-holdout split. The learned model achieved a ROC AUC of 0.7003 versus 0.6240 for the baseline, with F1 improving from 0.2882 to 0.5662—a 96% gain in discrimination. The output is a ranked queue that editors can use tomorrow to prioritize content review; the model is a triage and decision-support tool, not a causal proof of refresh impact. This report documents the problem, data choices, baseline, model, evaluation, and reproducible methodology.

1. Problem Framing

Decision: Should a content editor review and refresh this page?

Unit of analysis: Individual web pages with positive impressions and content age ≥ 90 days.

Output: A ranked queue of pages, scored by decline risk, so editors can focus human review effort on the highest-value candidates first.

Action: An editor reviews a ranked page and decides whether to update, rewrite, or refresh its content based on current trends and business context.

Cost of error: False positives waste editor time; false negatives leave declining pages unreviewed and risk continued traffic loss. A balanced approach is preferred.

Why ML helps: Hundreds of thousands of pages cannot be reviewed manually. Machine learning can capture non-linear relationships between page features (age, traffic, trend, position) and decline risk, enabling systematic triage at scale.

2. Data Safety

Data Used

The anonymized FlyRank starter dataset, specifically:

  • Pages with positive impressions in the evaluation period
  • Content age of at least 90 days (to exclude very new pages)
  • Features: impression volume, click volume, position, content age, and derived trend metrics

Columns Deliberately Excluded (and Why)

  • Page text, titles, URLs: Avoid leaking semantic information that could encode client identity or bias predictions.
  • Client-identifying fields (client ID, domain, brand): The model should not memorize client-specific patterns; it should generalize across clients.
  • User-identifying data: All user and session information excluded for privacy compliance.

Leakage Risk Assessment

  • Label leakage: The target (`decline`) is derived from trend direction over a held-out time window, not from any feature computed on the same window. ✓ Safe.
  • Temporal leakage: All features are computed on pages observed 90+ days before the evaluation period. ✓ Safe.
  • Client grouping: Client ID used only for holdout split (never as a feature). ✓ Safe.
  • Pseudonymous IDs: No page ID, client ID, or user ID appears in model features. ✓ Safe.

Confirmation: No client-identifying details appear in outputs, models, or this report.

3. Baseline

Baseline method: A transparent, rule-based refresh score combining three intuitive components:

  • Visibility: Pages with higher impression volume are ranked higher (more traffic = more impact if refreshed).
  • Freshness risk: Pages with older content are ranked higher (stale content is more likely to need refresh).
  • Position opportunity: Pages currently ranked outside top positions are ranked higher (more potential to improve).

Rationale: This baseline is fair because it uses the same feature set as the learned model, requires no training, and is explainable to domain experts.

Baseline performance (held-out split):

  • ROC AUC: 0.6240
  • Average Precision: 0.4661
  • Precision: 0.5069 | Recall: 0.2013 | F1: 0.2882

Baseline limitation: Low recall (0.2013) indicates the rule misses many declining pages, missing opportunities for timely refresh.

4. Model / Analysis

Method

Logistic regression is well-suited to this ranking and triage lane because:

  • It produces calibrated probabilities, which rank pages smoothly rather than in hard clusters.
  • It is interpretable: feature coefficients show which page properties drive decline risk.
  • It is fast to train and serve, enabling real-time scoring of new pages.
  • It avoids overfitting risk on a relatively modest feature set and data volume.

Feature List

  • Impression volume: Total impressions in the training window.
  • Click volume: Total clicks in the training window.
  • Current position: Average ranking position at the end of the training window.
  • Content age: Days since the page was last published or updated.
  • Click-through rate (CTR): Clicks / impressions.
  • Trend in impressions: Slope of impression counts over the training window.

Intentionally excluded: Client ID, page text/title, URL structure, user engagement, and semantic features. These are excluded to ensure the model generalizes across clients and avoids memorizing client-specific patterns.

Target Definition

Decline (target = 1): Pages where impression trend is negative and statistically significant in the evaluation window, relative to a baseline trend computed from the training window. In one sentence: A page is "in decline" if its impressions are trending downward at evaluation time.

Base rate: Approximately 30% of pages in the dataset show decline over the evaluation window.

5. Evaluation

Evaluation Split

Client-holdout split: Pages from a randomly selected 20% of clients are held out from training and used only for evaluation. This approach ensures the model has never seen data from the held-out clients, simulating realistic generalization to new clients.

Why this split: A client-holdout split is pragmatic and interpretable: it reflects how the model will perform on pages from new or unseen clients in production.

Error Analysis & Key Findings

Summary: The learned model substantially outperforms the baseline across all metrics.

  • Ranking quality (ROC AUC 0.7003 vs 0.6240): The model ranks declining pages higher than stable pages with 12.2% better discrimination than the rule-based baseline. A 0.70 AUC indicates the model is reasonably good at ranking, though not perfect.
  • Precision-Recall balance: The model achieves near-perfect balance (precision 0.5659, recall 0.5666) with F1 = 0.5662. The baseline's F1 of 0.2882 was driven by extremely low recall (0.2013), meaning it missed 80% of declining pages—a critical failure for a triage system.
  • Lift over baseline: F1 improved by 96%, showing the model is substantially more useful for editorial triage than the rule.

6. Interpretation

What the Model Found

The logistic regression model learned that pages are more likely to decline when they combine:

  • High impression volume but negative trend: Pages with historically high traffic but recently declining impressions are the highest-risk group for decline.
  • Older content: Content age has a strong positive coefficient, confirming editorial intuition: older pages are more likely to be stale.
  • Lower current position: Pages ranked lower in search or visibility are more vulnerable to further decline if not refreshed.
  • Declining click-through rate: Pages with falling CTR relative to historical patterns signal possible content quality or relevance drift.

Feature Importance (Qualitative)

The top drivers of decline risk are (in rough order of influence):

  1. Content age (strongest): Stale content is the dominant signal.
  2. Impression trend (strong): Declining traffic volume is the second-strongest signal.
  3. Current position (moderate): Lower-ranked pages are more at risk.
  4. CTR trend (moderate): Falling engagement signals possible drift.

Surprises & Negative Results

  • Absolute click volume matters less than trend: Pages with high absolute clicks but declining trends are riskier than pages with low but stable clicks. This reinforces that the model prioritizes velocity signals over absolute magnitude.
  • No "magic" feature: No single feature dominates the decision. The model is inherently multivariate—a realistic finding that reflects the complexity of decline.
  • Client-agnostic: The model generalizes across clients without client-specific features, confirming that page-level signals are portable across contexts.

7. Recommendation

How to Use This Model Tomorrow

FlyRank editors: Each morning, pull the ranked refresh queue (sorted by model score descending). Review the top N pages (e.g., top 50–100 per week). For each page:

  1. Read the page and assess its current relevance and accuracy.
  2. Check when it was last updated and whether trends/best practices have shifted.
  3. Decide: refresh (update with new information), rewrite (overhaul structure/depth), or deprioritize (leave as-is).
  4. Log the decision and outcome (e.g., did refresh lead to traffic recovery?).

Confidence & Limits

  • Confidence level: ROC AUC 0.70 means the model is "reasonably good" but not perfect. About 70% of the time, a randomly chosen declining page will score higher than a randomly chosen stable page—a meaningful but not overwhelming edge.
  • Best for ranking, not thresholds: Use the model's scores to order pages. Do not try to set a hard "refresh if score > X" threshold; the absolute score is less reliable than the relative ranking.
  • No causation: The model does not prove that refreshing a page will recover traffic. It only predicts which pages are currently in decline. Editorial judgment and business context must guide the final decision.
  • Drift risk: Real-world content and user behavior evolve. The model was trained on past data; its performance may degrade over months. Plan to retrain quarterly or when you notice significant drift in editor feedback.

8. Reproducibility

Commands to Re-Run Everything

From a fresh clone of the repository:

# Set up virtual environment
python -m venv .venv
source .venv/Scripts/activate  # Windows
pip install -r requirements.txt

# Run full pipeline
python scripts/run_all.py

# This will:
# 1. Prepare features (01_prepare_features.py)
# 2. Compute baseline score (02_baseline_score.py)
# 3. Train logistic regression model (03_train_model.py)
# 4. Evaluate and export metrics (04_evaluate_and_export.py)
# 5. Generate PDF report (05_build_pdf_report.py)
