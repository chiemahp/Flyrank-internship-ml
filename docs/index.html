FlyRank Ranking Analysis Capstone

This page summarizes the capstone analysis from the notebook and is designed to be published as a static GitHub Pages site.

Executive Summary

This capstone project develops a machine learning model to rank web pages for content refresh review. The analysis demonstrates that a logistic regression model significantly outperforms a transparent baseline rule for identifying pages that are likely declining in performance. The model achieved a ROC AUC of 0.7003 compared to 0.6240 for the baseline, with improvements across all key metrics. This model serves as a decision-support tool to help content editors prioritize their review efforts and allocate resources more effectively.

Introduction

Content management platforms face a continuous challenge: identifying which pages require refresh or updates. With millions of pages in production, manual review is impractical. The FlyRank system addresses this by building predictive models that identify pages most likely to be declining in performance and in need of editorial attention.

The decision supported here is whether a content editor should review a page for refresh. The ranking output is meant to focus attention on the highest-value review candidates, not to prove that any one intervention will improve outcomes. This distinction is crucial: the model is a triage tool, not a causal inference engine.

Objectives

  • Primary: Build a predictive model that accurately ranks web pages by their likelihood of decline, enabling efficient editor triage.
  • Secondary: Compare the performance of a machine-learned model against a transparent, rule-based baseline to validate the machine learning approach.
  • Tertiary: Ensure the model operates with explainability in mind, using only page-level features that do not rely on sensitive identifying information.

Methodology

Data and Scope

The analysis used the anonymized FlyRank starter dataset and scored pages with the following criteria:

  • Pages with positive impressions in the evaluation period
  • Content age of at least 90 days (to exclude very new pages)
  • Exclusion of page text, titles, URLs, and client-identifying fields to preserve privacy

The target variable was a directional label derived from trend analysis, capturing whether a page's performance is declining relative to its historical baseline.

Approach

Two competing models were evaluated on a client-holdout split:

  • Baseline Model: A transparent refresh score based on three rule-based components: visibility (impression volume), freshness risk (content age), and position opportunity (current ranking potential).
  • Learned Model: A logistic regression model trained on the same feature set, optimized to predict the decline target.

The client-holdout split ensures that pages from held-out clients are not used during training, providing a pragmatic proxy for real-world generalization.

Key Findings

  • Ranking Quality: The logistic regression model achieved a ROC AUC of 0.7003, representing a 12.2% improvement over the baseline (0.6240). ROC AUC measures the model's ability to rank positive examples (pages in decline) higher than negative examples (stable pages).
  • Precision and Recall Balance: The learned model achieved near-perfect balance between precision (0.5659) and recall (0.5666), resulting in an F1 score of 0.5662. This is substantially better than the baseline's F1 of 0.2882 (96.2% improvement), which suffered from very low recall (0.2013).
  • Average Precision: The model's average precision improved by 11.9% (0.5215 vs 0.4661), indicating better ranking of relevant items across different decision thresholds.

Model Performance Comparison

Limitations

  • Target Proxy: The target uses trend direction as a proxy for decline rather than a verified business outcome. Page decline in traffic does not directly prove that refresh is needed, nor does it guarantee that refresh will recover traffic.
  • Scope Constraints: The analysis includes only pages with positive impressions and content age of at least 90 days, limiting applicability to newly published or zero-traffic pages.
  • Generalization Risk: The client holdout is a pragmatic estimate of future generalization rather than a guarantee of live performance. Real-world drift, concept shift, or unobserved factors could affect production performance.
  • Feature Limitations: The model does not use content, URL structure, or client information, potentially leaving relevant signals on the table.
  • No Causal Evidence: This analysis supports triage, not causation. We cannot conclude that refreshing a high-ranked page will improve its performance.

Conclusion

The logistic regression model demonstrates clear superiority over the rule-based baseline in identifying pages likely to be in decline. The 12.2% improvement in ROC AUC and 96.2% improvement in F1 score provide strong evidence that machine learning can better capture the complex relationships between page features and decline risk. The model's balanced precision and recall make it well-suited for triage: editors can use it to focus human review effort on the highest-value candidates.

However, this improvement should not be overstated. The model is a tool for prioritization, not a causal intervention. Content editors should apply their domain expertise, editorial judgment, and business context when deciding whether to refresh a page. The ranked queue serves as a starting point for systematic review, not a replacement for human decision-making.

Recommendations

For Content Teams

  • Use the ranked refresh queue as a decision-support tool to systematically identify and prioritize pages for editorial review.
  • Apply domain expertise and business context when deciding whether to refresh a page; the model score should inform but not replace human judgment.
  • Track the outcomes of refresh decisions (e.g., whether refreshed pages recover traffic) to provide feedback on the model's real-world utility.

For Data Teams

  • Monitor model performance in production and retrain periodically to account for concept drift and evolving patterns in page performance.
  • Explore additional features (e.g., content freshness scores, semantic drift, engagement patterns) to further improve ranking accuracy.
  • Consider ensemble methods or more complex models if additional data and compute resources become available.
  • Implement A/B testing to measure the causal impact of using the ranked queue on editor efficiency and page performance outcomes.

For Leadership

  • Frame this model as a triage and prioritization tool, not as a direct causal predictor of refresh impact.
  • Use the baseline-to-model improvement (12.2% ROC AUC gain) as evidence of ML value in editorial workflows.
  • Plan for periodic model retraining and validation as the content landscape and user behavior evolve.
